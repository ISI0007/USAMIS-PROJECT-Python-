# Teacher instructions for USAMIS

The SQL file restores the complete fictional demonstration database. To see the website, run the included Python application as well. The database contains paths to the illustrated profiles; the actual PNG files are in the included `project/app/frontend/static/images/demo-avatars` folder.

## Requirements

- PostgreSQL 17 and its `psql` and `createdb` commands. This dump was generated by PostgreSQL 17; use PostgreSQL 17 and a recent PostgreSQL 17 `psql` client.
- Python 3.11 or 3.12 and the unzipped USAMIS project package.
- An existing PostgreSQL user that can create a database, such as `postgres`. Supply its password when prompted. If commands are not found, add the PostgreSQL `bin` directory to PATH or use its full path.

## 1. Restore the database in Windows Command Prompt

Open Command Prompt in this repository’s `deliverables` folder and run:

```cmd
createdb -h localhost -U postgres usamis_teacher_demo
psql -X -h localhost -U postgres -d usamis_teacher_demo -v ON_ERROR_STOP=1 -f USAMIS_Demo_Database.sql
```

Enter the PostgreSQL user's password whenever prompted. Create a **new empty** database: the dump creates tables and should not be loaded over an existing USAMIS database. If `usamis_teacher_demo` already exists, choose another new database name and use it consistently in the commands and configuration. An error stops the restore; do not continue until it succeeds.

## 2. Display the records in Command Prompt

From the same `deliverables` folder:

```cmd
psql -X -h localhost -U postgres -d usamis_teacher_demo -v ON_ERROR_STOP=1 -f USAMIS_Check_Database.sql
```

The summary shows counts, the eight students, two teachers and the synthetic training-data label. You can also explore interactively:

```cmd
psql -X -h localhost -U postgres -d usamis_teacher_demo
```

Inside `psql`, use `\dt` to list tables, `SELECT * FROM courses LIMIT 10;` to see sample courses, and `\q` to exit. The database includes academic and finance records, users, audit information, 600 synthetic training rows, the trained experiment and migration tracking.

## 3. Run the website

Change from `deliverables` to the repository root. In Command Prompt:

```cmd
cd ..
py -3.11 -m venv .venv
.venv\Scripts\activate.bat
python -m pip install -r requirements-vision.txt
copy .env.example .env
```

Open `.env` in a text editor. Set `SECRET_KEY` to a new long random value and set `DATABASE_URL` for your actual PostgreSQL credentials and the restored database, for example:

```text
DATABASE_URL=postgresql+psycopg2://postgres:YOUR_PASSWORD@localhost:5432/usamis_teacher_demo
```

Replace `YOUR_PASSWORD` with your PostgreSQL password. URL-encode special characters in the password when necessary. Save the file, then run:

```cmd
python scripts/check_schema.py
python -m flask --app wsgi run --host 127.0.0.1 --port 5055 --no-reload
```

The schema check should print `[]`. Open http://127.0.0.1:5055 in a browser. Sign in as `admin`, `t.mensah` or `s.demo`, using demo password `Demo_Pass1!`. Open People Directory, Neural Risk Experiment, and the academic modules. To demonstrate QR attendance, the teacher must open a **new** session because old session tokens expire and are signed with the original environment's secret.

The neural model uses synthetic data and its metrics are educational results, not verified accuracy on real students. The illustrations are fictional and are not model-training images. SMS and payment records are demonstrations; external providers were not tested.

## Verified

The supplied dump was restored into a new empty PostgreSQL database. The inspection script ran successfully, the application connected to that restored database, and the trained model loaded from its SQL research table even with no local JSON model file.
